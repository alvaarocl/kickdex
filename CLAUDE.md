# KICKDEX Agent Playbook

This file is the shared operating guide for Claude, Codex, or any other coding agent working on KICKDEX.

User instructions override this file. Read relevant code before editing. Keep changes scoped, tested, and deployable.

## Product Direction

KICKDEX is a static-first football intelligence product deployed on GitHub Pages.

Primary public product:
- `docs/index.html`
- `docs/css/app.css`
- `docs/js/*.js`
- `docs/data/*.json`

Data/product pipeline:
- `scripts/build_data.py`
- `app/data/*`
- `app/engine/*`
- `.github/workflows/update_data.yml`

Do not add new public backend dependencies unless explicitly approved. Static JSON generated by batch jobs is the default architecture.

## Launch Truths

Do not overstate coverage.

Current known limitations:
- Calendar has broad future coverage through FixtureDownload for top leagues, but not every second division.
- Player stats are season aggregates, not real match-by-match logs.
- Player coverage is strong for SP1, E0, I1, D1, F1; weak or missing for SP2, E1, I2, D2, F2, N1.
- Referee data is aggregate-heavy and source-dependent.
- Legal pages exist, but real owner identity fields must be completed before a commercial launch.

Copy must remain honest:
- Say "estimated edge", never "guaranteed edge".
- Say "informational/statistical", never "betting advice".
- If a feature depends on partial data, state the limitation in the UI.

## Critical Launch Blockers

### 1. Make Edge Real

The hero Edge Number must not be a hardcoded demo.

Minimum viable implementation:
1. Read Bet365 odds already present in football-data CSVs:
   - `B365H`
   - `B365D`
   - `B365A`
2. For upcoming fixtures, calculate model probabilities using existing Poisson logic.
3. Convert odds to implied probability: `1 / odds`.
4. Edge percentage:
   - `edge_pct = (model_probability - implied_probability) * 100`
5. Generate `docs/data/edges.json`.
6. Landing hero reads the best upcoming edge from `edges.json`.
7. Inicio cards show the computed edge when available.
8. Add tests for positive edge, negative edge, invalid odds, and no-edge cases.

Expected `edges.json` contract:

```json
{
  "updated_at": "2026-04-30T18:00:00Z",
  "source": "football-data.co.uk closing odds",
  "items": [
    {
      "league": "SP1",
      "date": "2026-05-01",
      "time": "21:00",
      "home": "Girona",
      "away": "Mallorca",
      "market": "home",
      "selection": "Girona",
      "bookmaker": "Bet365",
      "odds": 2.1,
      "model_probability": 0.52,
      "implied_probability": 0.4762,
      "edge_pct": 4.38,
      "confidence": "low"
    }
  ]
}
```

Important caveat:
- Football-data closing odds are not live odds. Label them honestly as historical/closing-book-derived estimates until a live odds API is added.

### 2. Stack Decision (resolved 2026-05-01)

Stack is **static-first**. All Streamlit/FastAPI/SQL artifacts have been removed:
- `main.py`, `Procfile`, `Dockerfile`, `railway.json`, `.streamlit/` → deleted.
- `app/ui/`, `app/api/`, `app/i18n.py` → deleted.
- `app/data/database.py`, `app/data/models.py`, `app/engine/query_engine.py` → deleted.
- `scripts/migrate_to_sql.py`, `kickdex.db`, `frontend/`, `.env.example` → deleted.

The public product is `docs/` on GitHub Pages. The Python pipeline (`app/data`, `app/engine`, `scripts/build_data.py`) runs as a batch job in CI and writes to `docs/data/*.json`. Do not reintroduce a public backend without explicit approval.

### 4. Coverage Page

Create `/coverage.html` or equivalent UI section.

It must show:
- Calendar coverage by league.
- Historical match depth by league.
- Player stats coverage by league.
- Referee coverage by league.
- Last update timestamp.

Use `docs/data/player_coverage.json`, `docs/data/referees.json`, `docs/data/fixtures.json`, `docs/data/meta.json`, and `docs/data/leagues.json`.

### 5. Methodology Page

Create `/methodology.html`.

Must explain:
- Data sources.
- Poisson model.
- Edge calculation.
- Closing odds vs live odds limitation.
- Referee and player data limitations.
- Responsible-use disclaimer.

## Legal and Regulatory Guardrails

KICKDEX must not present itself as betting advice.

Keep visible:
- "RISK NOTICE: edges are estimates, not guarantees."
- "Informational/statistical use."
- "No login. No ads. No picks."

If analytics are added:
- Prefer cookieless analytics.
- Update `cookies.html` and `privacidad.html`.
- Add consent if required.

Before commercial launch:
- Complete legal owner fields.
- Confirm DGOJ-facing copy is conservative.
- Review pages with a qualified legal professional if monetization involves betting-adjacent services.
